# T1: Überlebt eine offene Sitzung Passwortwechsel und NOLOGIN?

Aus `/home/nikita/docker/ba-test`. Drei Terminals.

## Vorbereitung (Terminal B)

```bash
V=vektoren/offene-fragen
docker compose down -v && docker compose up -d --wait
docker compose exec -T pg-service psql -U ba_admin -d ba_test -f - < $V/setup.sql
```

## Sitzungen öffnen

Terminal A (Opfer, bleibt die ganze Zeit offen):
```bash
docker compose exec -e PGPASSWORD=alt pg-service psql -h ba-test-pg -U t_victim -d ba_test
```

Terminal B (Superuser):
```bash
docker compose exec pg-service psql -U ba_admin -d ba_test
```

## Ablauf

| Schritt | Terminal | Befehl | Erwartung |
|---|---|---|---|
| 1 | A | `SELECT version();` | Version notieren |
| 2 | A | `SELECT * FROM t_data;` | 1 Zeile |
| 3 | B | `ALTER ROLE t_victim PASSWORD 'neu';` | ALTER ROLE |
| 4 | A | `SELECT * FROM t_data;` | 1 Zeile, Sitzung lebt |
| 5 | B | `ALTER ROLE t_victim NOLOGIN;` | ALTER ROLE |
| 6 | A | `SELECT * FROM t_data;` | 1 Zeile, Sitzung lebt |
| 7 | B | `SELECT pid, usename, state FROM pg_stat_activity WHERE usename = 't_victim';` | 1 Zeile, pid notieren |
| 8 | B | `SELECT pg_terminate_backend(pid) FROM pg_stat_activity WHERE usename = 't_victim';` | t |
| 9 | A | `SELECT * FROM t_data;` | `terminating connection due to administrator command` |

## Neue Anmeldung (Terminal C)

Kontrolle, dass über `ba-test-pg` das Passwort geprüft wird:
```bash
docker compose exec -e PGPASSWORD=falsch pg-service psql -h ba-test-pg -U ba_admin -d ba_test -c 'SELECT 1'
```
Erwartung: `password authentication failed for user "ba_admin"`

Altes Passwort (muss scheitern):
```bash
docker compose exec -e PGPASSWORD=alt pg-service psql -h ba-test-pg -U t_victim -d ba_test -c 'SELECT 1'
```
Erwartung: `password authentication failed for user "t_victim"` oder
`role "t_victim" is not permitted to log in`. Offen ist, welche der
beiden Prüfungen PostgreSQL zuerst ausführt.

Neues Passwort (muss scheitern):
```bash
docker compose exec -e PGPASSWORD=neu pg-service psql -h ba-test-pg -U t_victim -d ba_test -c 'SELECT 1'
```
Erwartung: `role "t_victim" is not permitted to log in`
